## #база
- Цель: перенести exteraGram (Android-клиент Telegram: функции + плагины на Python) на ПК.
- Основа: Telegram Desktop 7.3.5 (C++/Qt 6). Выбрана, потому что слой API 232 совпадает с exteraGram 13.1.1; в 7.4 уже 233.
- Название программы: extera Desktop. Автор сборки в описании: vixn_n.
- Репозиторий: `tnt-cat/exera-desktop` (форк telegramdesktop/tdesktop, открытый).
- Ветки: `exg` — рабочий код; `status` — только этот файл; `dev` — ветка по умолчанию от Telegram, не трогаем.
- Источники знаний об exteraGram: два документа проекта (`Main`, `API`) и файл `Full classes` (10 МБ, все классы; пользователь прикладывает при необходимости).
- Компьютер пользователя: старый ноутбук, Windows 10, 4 ГБ памяти — собирать на нём нельзя.

## #правила
- Отвечать коротко, с главного: пользователь читает с телефона, новичок, код сам не пишет.
- Ничего не придумывать (названия, классы, функции, поведение). Чего нет в файлах — сказать и спросить.
- Сборку запускать только по слову «собери». Никаких задач по расписанию без просьбы.
- API_ID и API_HASH в чат не писать, они в секретах репозитория.
- Коммиты по `AGENTS.md`: короткая тема, без строк Co-Authored-By.
- В контекст и память проекта ничего не добавлять без согласия.
- Экономить лимит: один чат — один этап, замечания и скрины пачкой.
- Картинку с Человеком-пауком на иконку не ставим (чужой персонаж и подпись художника), стоит котик.
- Этот файл открытый: личных данных и ключей сюда не писать.

## #сборка
- Только GitHub Actions: `.github/workflows/exg-win.yml`, запуск вручную (workflow_dispatch) на ветке `exg`. Около 75 минут, библиотеки берутся из кеша.
- Сборка отладочная (Debug): exe 565 МБ, архив 146 МБ.
- Последняя успешная сборка: коммит `2f65299`.
- Ещё не собирались: `5b89cfc` иконка, `b6edec7` переименования, `f6c02d1` описание, `174a841` система плагинов, `994468f` сверка SDK и шесть коммитов окна плагинов: `00952be`, `fa24e6e`, `66ab606`, `82d705a`, `4d96797`, `f2e7d0b`.
- Весь код окна плагинов писался без компилятора. Первая сборка почти наверняка упадёт на ошибках компиляции: править по журналу сборки и собирать снова.
- В начале сборки скачивается Python 3.11.9 (embeddable), ставится `requests`, прогоняются тесты движка.
- Архив: `extera.exe` + папки `python` и `extera`. Распаковывать целиком в постоянную папку, новую сборку — поверх старой. Вход хранится в `tdata` рядом с exe. Запуск прямо из zip не подходит.

## #код
- `Telegram/SourceFiles/extera/extera_python.*` — загрузка `python311.dll` из папки `python` рядом с exe, вызовы в Python. Сборка от Python не зависит.
- `Telegram/SourceFiles/extera/extera_plugins.*` — сторона программы: журнал, тосты, диалоги, отправка текста, перехват отправки.
- `Telegram/SourceFiles/extera/extera_plugins_box.*` — окно «Плагины» (две части для широкого окна, колонка карточек для узкого), окно установки, страница «Система плагинов», окно «Неизвестные источники», картинки плагинов из стикеров.
- `Telegram/SourceFiles/extera/extera.style` — размеры и цвета этих окон, подключён в `Telegram/cmake/td_ui.cmake`.
- Настройки системы плагинов лежат в `extera/data/options.json` рабочей папки (`engine`, `safe_mode`, `confirm_sensitive`, `unknown_sources`); читать и менять через `PluginsOption` / `SetPluginsOption` в `extera_plugins.*`.
- Точки врезки: `ApiWrap::sendMessage` (перехват отправки), `Core::Application::run` (запуск движка), `settings_main.cpp` и `window_main_menu.cpp` (пункт «Плагины»), `Data::ResolveDocument` в `data_document_resolver.cpp` (нажатие на файл `.plugin` в чате).
- `extera/sdk/` — движок и SDK на Python; `extera/tests/` — тесты (`test_engine.py`, `test_bridge.py`).

## #движок
- `extera_engine.py` — загрузка плагинов, хуки, меню, настройки. `extera_bridge.py` — единая точка `call(имя, json)` для программы. `extera_scan.py` — разовая проверка плагина при установке.
- Java-импорты плагинов не падают: класс с аналогом на ПК подменяется, остальные становятся заглушками, которые ругаются только при использовании.
- Плагины лежат в `extera/plugins` рабочей папки, настройки — в `extera/data`. Флаги «включён» и «закреплён» — в `extera/data/plugins.json`.
- Команды моста для окна: `list` (в ответе есть `pinned`, `path`, `icon`, `has_settings`), `inspect` (проверка файла до установки), `install` (с параметром `enable`), `set_enabled`, `set_pinned`, `set_mode` (движок и безопасный режим), `about` (версия SDK), `delete`.
- В безопасном режиме и при выключенном движке ни один плагин не загружается; включить плагин в безопасном режиме нельзя.
- Умеют: перехват и изменение отправляемого текста, команды, тосты, диалоги, отправка текста с разметкой, копирование, открытие ссылок, свои настройки, пункты главного меню (показаны в окне «Плагины»).
- Не умеют: запросы к серверу Telegram, входящие обновления, отправка файлов, пункты меню чата/сообщения/профиля, перехваты Java-методов, Android-интерфейс, формат Elyx.

## #окно-плагинов
- Ничего из этого тега не собиралось и на экране не проверялось.
- Открывается из бокового меню и из настроек, поверх чатов по центру.
- Пользователь просил не копировать телефон, а перенести под ПК. Выбран вид из двух частей.
- Широкое окно программы (примерно от 690 пикселей): слева поиск, переключатель «Система плагинов», список плагинов с переключателями, «Действия плагинов», серая строка «Каталог плагинов». Справа выбранный плагин: картинка, название, версия и автор, описание, ошибка запуска, кнопки «Поделиться», «Открыть файл», «Закрепить» / «Открепить», «Удалить плагин», ниже его настройки.
- Узкое окно программы: колонка карточек как на телефоне (название, версия и автор, переключатель, описание, кнопки значками), поиск по кнопке, без картинок.
- Закреплённые плагины идут первыми. Настройки показываются только у включённого плагина, у которого они есть.
- Кнопка (i) открывает «Систему плагинов». Работают: «Неизвестные источники», «Подтверждать важные действия» (пока только хранится), «Безопасный режим», версия SDK, «Установить из файла», «Открыть папку плагинов», «Скопировать журнал плагинов». Серые, по нажатию пишут «Пока недоступно на ПК»: «Режим разработчика», «Компактный вид плагинов», «Режим совместимости», «Статический анализ», три пункта обновления SDK, «Документация», «Проверенные плагины». Пользователь сказал: потом лишнее удалим.
- Окно установки: по нажатию на `.plugin` в чате (файл сначала скачивается) и из «Установить из файла». В нём картинка или стандартный значок, название, версия (при обновлении старая зачёркнута), пометка «Неизвестный источник», описание, пометка статуса с причиной, «Установить» / «Обновить», галочка «Включить после установки» (по умолчанию снята).
- Пометки статуса (#статусы) придумал пользователь, на телефоне их нет. Показываются только в окне установки.
- «Неизвестные источники»: по умолчанию выключено. Включение — окно с тремя пунктами, красным предупреждением и кнопкой «Разрешить» с отсчётом 30 секунд. Выключение сразу. Пока выключено, в окне установки кнопка «Установка заблокирована» не нажимается.
- Списка проверенных каналов нет, поэтому сейчас любой плагин считается неизвестным: пока переключатель выключен, не установится ничего.
- Удаление: окно «Удалить плагин», текст «Вы уверены, что хотите удалить …?», кнопки «Отмена» и «Удалить».
- Картинка плагина — стикер из `__icon__` (см. #sdk). Без неё в списке пусто, в окне установки стандартный значок.
- «Компактный вид» на телефоне: картинка рядом с названием; обычный вид — картинка сверху; по умолчанию выключен. На ПК пока серый.
- Каталог по скринам: список проверенных каналов; внутри канала вкладки категорий, разделы «Обновления», «Установленные», «Все плагины», сортировка (недавно обновлённые, популярные, новые, по названию). Не сделан.
- Блок сканера в окне установки («Есть предупреждения», метки «Аккаунт», «Сообщения» и т. д.) пользователь сказал пока не добавлять.

## #статусы
- Работает — плагину хватает того, что есть на ПК.
- Частично — есть перехваты Android-методов или классы Android-интерфейса.
- Не работает — внутри скомпилированный Android-код или ошибка в коде.
- Не для ПК — про функции телефона (камера, кружки, виджеты и т. п.). Такие и «Не работает» при установке выключены.
- Отбор «не для ПК» автоматический и грубый.

## #sdk
- Образец: SDK плагинов exteraGram 1.4.6.3, Python 3.11.
- Сверено с настоящими сигнатурами из документа `API`: 18 модулей, расхождения исправлены. Из 105 имён SDK, которые используют реальные плагины, есть 87; остальных 18 нет и в настоящем SDK.
- `extera_utils.classes` (создание Java-классов) — только заглушки, это чисто Android.
- Точные правила разметки `parse_markdown` в файлах не описаны; принимаются и `*жирный*`, и `**жирный**`.
- Не проверено (пользователь попросил остановиться): аргументы методов Android, часть поведения движка по описанию.
- `__icon__` принимает только стикер вида `ИмяНабора/номер`, счёт с нуля; имя набора — то, что в ссылке `t.me/addstickers/ИмяНабора`. Имя вроде `msg_retry` в 13.1.1 не работает, в документе `Main` тут ошибка (проверил пользователь). `icon=` в пунктах меню и настройках — наоборот, имя `msg_*`.
- `__category__` — список категорий плагина для каталога. Движок его пока не читает.

## #статистика
- Просканировано 584 плагина из 13 каналов (сканер — отдельный плагин для телефона).
- По сложности: 4% только верхний API, 6% только помощники, 23% Android-интерфейс, около 50% интерфейс + перехваты Java, 16% со встроенным dex.
- После отбора: 94 с dex, 59 только для телефона, 430 остаётся.

## #безопасность
- В exteraGram есть «Подтверждение чувствительных запросов» (`com.exteragram.messenger.security.SensitiveRequestConfirmation`, `SensitiveRequestSheet`, `SensitiveRequestSwitch`).
- Окно снизу: «Подтвердите действие», аккаунт, название запроса, «Разрешить» / «Отклонить».
- Категории: платежи, управление чатами, вход в аккаунт (пример: `auth.acceptLoginToken`).
- Список защищённых запросов спрятан в нативном коде, в файлах его нет.
- На ПК делать вместе с запросами плагинов к Telegram, проверку — в C++, чтобы плагин не обошёл.
- Переключатель «Подтверждать важные действия» уже есть в «Системе плагинов», по умолчанию включён, значение хранится. Самой проверки пока нет.

## #обновление
- Пользователь хочет кнопку «Обновить». Предложено два варианта, выбор не сделан.
- Вариант 1: сборки выкладываются в Releases, в программе кнопка «Проверить обновления» (скачать, заменить, перезапустить).
- Вариант 2: `update.bat` рядом с exe.
- Учесть: Releases открыты всем, API-ключи зашиты в exe; архив 146 МБ на каждое обновление.

## #ресурсы
- Из Android нельзя взять готовые кнопки и окна (другой код отрисовки). Можно взять иконки, тексты, цвета, размеры, анимации.
- В имеющихся файлах только названия иконок и строк. Для настоящих нужен APK exteraGram 13.1.1 (129 МБ) или папка `res`.
- Перед тем как класть чужие иконки в открытый репозиторий, проверить лицензию exteraGram.

## #скрины
- Получены и разобраны: список плагинов в обоих видах, окно установки и обновления, «Система плагинов», «Неизвестные источники», удаление плагина, каталог (список каналов, канал, сортировка), «Подтвердите действие».
- Иконка папки на карточках плагинов на скринах — от стороннего плагина, переносить не нужно.
